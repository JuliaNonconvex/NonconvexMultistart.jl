NonconvexMultistart.DeflatedAlg — Type
DeflatedAlg(sub_alg)

Deflation meta-algorithm for finding multiple distinct local minimizers of a non-convex problem. It repeatedly solves the problem with the sub-solver sub_alg, starting from the same initial point each time, while adding a deflation (inequality) constraint that pushes the solver away from all previously found solutions, as proposed in:

Mohamed Tarek and Yijiang Huang. "Simplifying deflation for non-convex optimization with applications in Bayesian inference and topology optimization", arXiv:2201.11926 (2022).

sub_alg can be any optimizer of the Nonconvex ecosystem that supports nonlinear inequality constraints. After k solutions x₁, …, xₖ have been found, the (k+1)-th sub-problem adds the variable y ∈ [0, y_upper] and the constraint

\[∑_{j=1}^{k} (max(d(x, x_j) - radius, 0)^{-p} + σ) ≤ y\]

where d(x, x_j) is the (possibly weighted or user-defined) distance between x and the j-th found minimizer x_j, and p, σ and radius are set through DeflationOptions. A solution of the deflated sub-problem with a finite y is a KKT point of the original problem that is distinct from x₁, …, xₖ (Lemma 4.1 of the paper).

alg = DeflatedAlg(IpoptAlg())
options = DeflationOptions(sub_options = IpoptOptions(), iters = 10)
NonconvexMultistart.DeflationMultistartAlg — Type
DeflationMultistartAlg(multi_alg)

Deflation meta-algorithm that combines deflation with an existing multistart meta-algorithm multi_alg, e.g. HyperoptAlg(IpoptAlg()). Instead of re-solving the deflated sub-problems from the same initial point with a single sub-solver, every deflation round runs a full multistart search of the deflated sub-problem, so both the deflation constraints and the multistart sampler work together to find new, distinct minimizers.

The deflation constraint uses the fixed-bound formulation (Lemma 4.2 of the paper): after k solutions x₁, …, xₖ have been found, the (k+1)-th sub-problem adds the constraint

\[∑_{j=1}^{k} (max(d(x, x_j) - radius, 0)^{-p} + σ) ≤ y_upper\]

with no auxiliary variable, so the multistart sampler explores only the original variables. p, σ, radius, the distance d and y_upper are set through DeflationMultistartOptions, which also carries the options of multi_alg.

alg = DeflationMultistartAlg(HyperoptAlg(IpoptAlg()))
options = DeflationMultistartOptions(
    multi_options = HyperoptOptions(sub_options = IpoptOptions(), iters = 10),
    iters = 4,
)
NonconvexMultistart.DeflationMultistartOptions — Type
DeflationMultistartOptions(; kwargs...)

Options for DeflationMultistartAlg. The fields are:

  • multi_options: the options of the wrapped multistart meta-algorithm, e.g. HyperoptOptions when the algorithm is a DeflationMultistartAlg(HyperoptAlg(...)).
  • iters: the maximum number of deflation rounds to run, i.e. the maximum number of distinct minimizers to find, 10 by default. Each round is one full multistart solve of the deflated sub-problem.
  • p, sigma, radius, distance and weight: the deflation hyperparameters, see DeflationOptions.
  • y_upper: the fixed bound M of the deflation constraint ∑ⱼ m(x; xⱼ) ≤ M (Lemma 4.2 of the paper), 1e8 by default. No auxiliary variable is added, so the multistart sampler explores only the original variables. The constraint excludes a hyper-ball of radius (y_upper - K̃σ)⁻¹ᐟᵖ around each known solution, where K̃ is the number of known solutions.
  • ctol: the infeasibility tolerance for accepting a sub-problem solution as feasible, 1e-5 by default.
  • tol: the distance tolerance used to decide that a new solution is identical to a previously found one, 1e-6 by default. A new solution is accepted only if it is farther than max(tol, radius + 100·(y_upper - K̃σ)⁻¹ᐟᵖ) from every known solution in the configured distance.
  • flags: a label (a Symbol, or a collection of Symbols) attached to the deflation constraint added to each sub-problem, [:deflation] by default; see DeflationOptions. Pass flags = nothing for no label.
  • keep_all: if true (the default), all the sub-problem results are kept in the results field of the returned DeflationResult.
NonconvexMultistart.DeflationOptions — Type
DeflationOptions(; kwargs...)

Options for DeflatedAlg. The fields are:

  • sub_options: the options of the sub-optimizer, or a function from the deflation iteration index to the sub-optimizer options.
  • iters: the maximum number of deflation sub-problems to solve, i.e. the maximum number of distinct minimizers to find, 10 by default.
  • p: the deflation power in d(x, x_j)⁻ᵖ, 2.0 by default. Larger powers concentrate the deflation effect closer to the known solutions.
  • sigma: the shift σ added to every deflation term, 0.0 by default. σ > 0 bounds the deflation function away from zero, which can help the convergence of the sub-solver.
  • radius: the radius r of the hyper-ball around each known solution inside which all points are deflated identically, 0.0 by default. With radius > 0, every new solution is guaranteed to be at least radius away from all previously found ones (in the chosen distance), even if deflation fails to find a new minimizer.
  • distance: an optional custom distance function d(x, x_j) returning a non-negative number, e.g. to deflate in a transformed space. By default the Euclidean distance is used.
  • weight: an optional positive semi-definite matrix Q giving the generalized Euclidean distance sqrt((x - x_j)' Q (x - x_j)). A diagonal Q can be used to weigh the deviations per coordinate. Only one of distance and weight can be set.
  • y_upper: the finite upper bound on the deflation variable y, 1e8 by default. The deflation constraint excludes a hyper-ball of radius (y_upper - K̃σ)⁻¹ᐟᵖ around each known solution, where K̃ is the number of known solutions. If deflation fails, the sub-solver converges to the boundary of that ball; such a point is reported as unsuccessful (see tol). A larger y_upper allows solutions closer to the known ones to be considered distinct.
  • ctol: the infeasibility tolerance for accepting a sub-problem solution as feasible, 1e-5 by default.
  • tol: the distance tolerance used to decide that a new solution is identical to a previously found one, 1e-6 by default. A new solution is accepted only if it is farther than max(tol, radius + 100·(y_upper - K̃σ)⁻¹ᐟᵖ) from every known solution in the configured distance; see deflation_failed for the exact acceptance criterion.
  • flags: a label (a Symbol, or a collection of Symbols) attached to the deflation constraint added to each sub-problem, [:deflation] by default. Inner optimizers that select constraints by label can use it to treat the deflation constraint in a custom way, e.g. RelaxConstraintSelection(labels = [:deflation]) in an augmented Lagrangian or barrier method; optimizers that do not inspect flags (e.g. Ipopt, MMA) simply ignore them. Pass flags = nothing for no label.
  • keep_all: if true (the default), all the sub-problem results are kept in the results field of the returned DeflationResult.
NonconvexMultistart.DeflationResult — Type
DeflationResult

The result of DeflatedAlg and DeflationMultistartAlg, with the following fields:

  • minimum: the best objective value among the found minimizers.
  • minimizer: the found minimizer with the best objective value.
  • minimizers: all the distinct feasible minimizers found, in the order they were found (in the flattened variable space).
  • results: all the sub-problem results when keep_all = true, nothing otherwise.
  • converged: true if all iters deflation iterations produced feasible solutions that are distinct from all previously found ones.
  • niters: the number of sub-problems actually solved before stopping.
NonconvexMultistart.HyperoptAlg — Type
HyperoptAlg(sub_alg)

Multi-start meta-algorithm: repeatedly solves the problem with the sub-solver sub_alg from different starting points chosen by a Hyperopt.jl sampler, and returns the best solution found. sub_alg can be any optimizer of the Nonconvex ecosystem. All constraint capabilities are forwarded from sub_alg; the starting-point search itself requires finite bounds (given explicitly through HyperoptOptions or taken from the model).

alg = HyperoptAlg(IpoptAlg())
options = HyperoptOptions(sub_options = IpoptOptions(), iters = 20)
NonconvexMultistart.HyperoptOptions — Type
HyperoptOptions: options performing starting point optimization using Hyperopt.jl
  • sub_options: options for the sub-optimizer.
  • lb: Lower bound of starting point, if don't specify it, the default value will be nothing, then will end up be replaced by the lower bound of optimization problem.
  • ub: Upper bound of starting point, same as above.
  • searchspace_size::Integer: How many potential starting points we generate.
  • iters::Integer: Among all generated potential starting points, how many of them will be evaluated.
  • sampler::Hyperopt.Sampler: An instance of 'Hyperopt.Sampler', which decides search algorithm.
  • ctol: infeasibility tolerance for accepting a solution as feasible
  • keep_all: if true, all the solutions of the sub-problems will be saved
NonconvexMultistart.HyperoptResult — Type
HyperoptResult

When using multiple x0 in optimize, return this result, including following fields:

  • minimum: the optimal value among all searches.
  • minimizer: the optimal solutions found.
  • results: all the search results.
  • optimal_ind: the index of the optimal solution in results.

NonconvexMultistart._copy_model_for_deflation — Method

A copy of model whose box and constraint containers are freshly allocated, so variables and constraints can be appended without mutating the original. The inequality constraint container is rebuilt with an abstract element type: tovecmodel stores constraint containers as tuples (empty ones are immutable, so constraints cannot be appended to them), and concrete-element vectors cannot hold the deflation constraint.

NonconvexMultistart._deflation_bound — Method

The upper bound of the deflation constraint: the y_upper field of both options structs, used as the auxiliary variable bound by DeflatedAlg and as the fixed bound M by DeflationMultistartAlg.

NonconvexMultistart._deflation_solver — Method

The solver used to solve the deflated sub-problems: the sub-solver of DeflatedAlg or the wrapped multistart algorithm of DeflationMultistartAlg.

NonconvexMultistart._deflation_sub_options — Method

The options of the solver used for the i-th deflation sub-problem.

NonconvexMultistart._deflation_threshold — Method

The distinctness threshold: the minimum distance (in the configured distance) between a new solution and every known solution.

NonconvexMultistart._normalize_flags — Method

Normalizes the flags argument (a Symbol, a String, or a collection of Symbols) to a Set{Symbol}. nothing yields the empty set.

NonconvexMultistart._prepare_deflated_model — Method

The shared preparation of the deflated model: checks the feasibility of the deflation bounds, snapshots the found solutions (so later additions to found do not change the constraint) and copies the model. Returns nothing when no solution has been found yet (no deflation constraint is added).

NonconvexMultistart._validate_deflation_parameters — Method

Validates the deflation hyperparameters shared by DeflationOptions and DeflationMultistartOptions.

NonconvexMultistart.check_deflation_capabilities — Method

Validates that the solver can handle the deflated sub-problems: they add a nonlinear inequality constraint, so a solver without that capability would fail only after the first (undeflated) solve. A dummy deflated model is built to reuse the exact capability machinery and error messages of checksubproblem!.

NonconvexMultistart.deflated_model — Method

Builds the model of the next deflation sub-problem for DeflationMultistartAlg: the original model extended with the fixed-bound deflation constraint ∑ⱼ m(x; xⱼ) ≤ y_upper over the previously found solutions, labeled with the flags of options. No auxiliary variable is added, so the multistart sampler explores only the original variables. When no solution has been found yet, the original model and x0 are returned unchanged.

NonconvexMultistart.deflated_model — Method

Builds the model of the next deflation sub-problem for DeflatedAlg: the original model extended with the deflation variable y ∈ [k·σ, y_upper] and the constraint ∑ⱼ m(x; xⱼ) ≤ y over the previously found solutions, labeled with the flags of options. Returns the model and a feasible starting point [x0; y0] where y0 is the value of the deflation constraint at x0 (plus a small margin), clipped to the bounds of y. When no solution has been found yet, the original model and x0 are returned unchanged.

NonconvexMultistart.deflation_distance — Method

The distance between x and a known solution x_k, as configured in options: a custom function, a Q-weighted Euclidean distance, or the plain Euclidean distance.

NonconvexMultistart.deflation_failed — Method

Returns true when the new point x is not a new distinct solution. Two signals are used:

  1. x is too close to a previously found solution in the configured distance: closer than max(tol, radius + 100·(y_upper - K̃σ)⁻¹ᐟᵖ) where K̃ is the number of known solutions. The second term accounts for the exclusion region around each known solution (Section 4.5 of the paper): a solver that fails to escape to a new minimizer converges to the boundary of that region, possibly overshooting it by an amount that depends on the solver's tolerances.
  2. The deflation constraint is active at (numerically) its upper bound y_upper, i.e. the solver converged to a point on the exclusion boundary at the cap.
NonconvexMultistart.deflation_function — Method

The deflation function m(x; x_k) = max(d(x, x_k) - radius, 0)⁻ᵖ + sigma.

NonconvexMultistart.deflation_result — Method

Assembles the DeflationResult from the recorded sub-results and found minimizers.

NonconvexMultistart.deflation_sum — Method

The sum of the deflation functions over all previously found solutions.
